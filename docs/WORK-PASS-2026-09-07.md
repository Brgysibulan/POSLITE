# SariPOS Work Pass — 2026-09-07

## Scope

Repository: `Brgysibulan/POSLITE`  
Primary target: native Android SariPOS  
Branch: `main`

This pass was started as a repository cleanup/hardening pass before larger native Android UX changes.

## Audit findings

1. The native launcher already shows **SariPOS**, but some internal/native startup branding still used the former `POSlite` development name.
2. The native Compose theme was light-only even though the project direction already includes System/Light/Dark appearance behavior.
3. Existing installs created with the old default store profile could still show `POSlite Store` as the store name.
4. The Android GitHub Actions workflow and uploaded artifact still used the old `POSlite` name.
5. The legacy receipt compatibility wrapper still mentioned `Pictures/POSlite`, even though current JPG receipts save under `Pictures/SariPOS`.
6. The current native **Benta** screen is still a two-column products/cart layout. This is usable on wider screens but remains the highest-priority phone portrait UX issue for the next pass.

## Implemented in this pass

### Native startup and theme

- Renamed the Compose theme entry point from the old development name to `SariPOSTheme`.
- Added automatic **system dark mode** support using Material 3 dark/light color schemes.
- Preserved the SariPOS green/yellow/red visual identity in both themes.
- Added a safe startup migration for the exact legacy default store name `POSlite Store` → `SariPOS Store`.
- Custom store names are not overwritten.

### Android build workflow

- Workflow display name changed to **Build SariPOS Native Android**.
- Uploaded debug artifact renamed to **SariPOS-native-debug**.
- Build command, SDK, Gradle and APK path remain unchanged to avoid destabilizing the working native build.

### Receipt compatibility cleanup

- Legacy compatibility wrapper now describes the current JPG-only behavior.
- Saved-receipt feedback now points to `Pictures/SariPOS`.
- Error feedback remains guarded so receipt export failures do not close the app.

## Safety / compatibility decisions

- Package name `ph.poslite.app`, SQLite file `poslite-native.db`, theme resource identifiers, and other internal compatibility IDs were intentionally **not** force-renamed in this pass. Renaming those without a migration could break upgrades or make existing local data appear missing.
- No sales, stock, purchase, credit, expense, analytics, or receipt database rules were changed.
- No existing user-defined store name is replaced by the branding migration.
